# 使用已有 Agent Reach 在线采集

这是宿主可选通道，不是 Guidekeep 的安装依赖。宿主内置或已连接工具已取得完整资料时直接继续归档；缺少工具入口、解析失败或资料不全时，使用本机已安装且获准的 Agent Reach。不得自动运行 setup、add、update、登录、浏览器扩展安装、Cookie 导入或付费转录来完成一次普通采集。

## 发现与调用

1. 若已安装 agent-reach skill，先读取其 SKILL.md 并遵守相应渠道规则；只读取本次动作需要的参考。Windows 用 `Get-Command agent-reach`，其他系统用 `command -v agent-reach`。若只是 PATH 缺失，核对现有 uv 工具目录中的入口，不重复安装，也不把机器上的绝对路径写成可移植依赖。
2. 执行 `agent-reach version` 确认版本；参数或渠道未知时执行 `agent-reach channels`。`doctor` 只是离线状态；安装成功和 unverified 均不能替代本次正文读取。
3. 不需要 MCP 工具命名空间或本机 Edge 连接。直接通过现有终端执行命令；出现终端沙箱/联网许可问题时使用宿主许可流程，不伪报网站 403，不让用户重复开对话来等待工具注入。

Windows 的 uv 入口若报 `uv trampoline failed to canonicalize script path`，或访问现有 uv 缓存时误报无法创建目录/文件已存在，先区分沙箱访问限制与真实安装故障。通过宿主正常许可流程，在有权访问现有工具目录及缓存的执行环境中复测同一条 `agent-reach version`；不要自行关闭沙箱、修改全局权限或先重装。如果正常授权环境成功返回版本，随后在该环境验证 channels 和实际读取，使用同一获准执行方式继续任务；这属于调用环境问题。仅当正常授权环境也失败时才进一步诊断安装、路径或依赖。把两种环境及结果记入事件，不向公开产物写入个人绝对路径。

按 URL 自动选择渠道：

```text
agent-reach read "INPUT_URL"
```

本机 Agent Reach 1.6.1 的 `channels` 声明 web/read 支持 jina 和 exa。实测默认链路曾耗尽30秒预算，而已存在的 Exa 后端可读取同一公开页面。对普通网页，已核对该动作和后端可用时可直接使用：

```text
agent-reach web read "INPUT_URL" --backend exa --timeout 45
```

这是可用性选择，不是规避网站限制；后端名和参数须以本机 channels 为准。平台专用链接优先按所声明动作调用，不能把 web/read 的参数套给所有渠道。既有 Edge、MCP 或 Agent Reach 返回明确验证墙/限流/登录要求时，不用该命令绕过。

## 读取 JSON，不只看退出码

1.6.1 的 read 响应在**顶层**包含 `ok/channel/action/backend/items/meta/error`；正文是 `items[].text`，不是 `result.items`。version 等管理命令的元数据可能在 result，不混用两种结构。保留原始 JSON 作为项目外的采集证据。

- `ok=true` 后仍检查每条 text 的正文首尾、章节、代码、分页和截断提示；只返回摘要、访问提示页或目录时不能记为完整。items 为空也不算成功。
- 标题、作者或日期可能为 null。只能从本次返回的明确标题/署名/日期，或正常取得的公开页面补充；不能按 URL 猜测。不把请求时间冒充发布时间。
- `url/final_url` 采用真实来源地址；保留 backend、meta.attempts、错误阶段与时间到 collect 事件。读取服务的代理地址不是文章 final_url；没有原站状态码时记“未知”。正常完成的内部诊断可记 ok，阅读页突出来源、缺失与限制。
- 文本阅读器可能省略图片 URL、图注、表格结构，或把代码行号混入配置。完整归档须用正常公开页面及其资源补全；只有全部正文、代码和原图已保留才记 complete。不能补全时保留实际文本并记 partial 与缺失范围，不因 ok=true 就宣称完整图文采集。

本机1.6.1的 Exa 网页读取实现请求 maxCharacters=20000；这不是“完整正文”的保证。即使返回长度未达到该上限，也须核对正文首尾与代码结构，不能用长度阈值替代完整性检查。

Agent Reach 的网页读取能力不是所有网站均可访问的承诺，也不是浏览器宿主修复。对已授权的公开转载仍按主指令保留原站失败记录，并明确标注实际版本。

## 有界失败处理

- TIMEOUT、UPSTREAM_BROKEN：记录 error 与 meta.attempts，检查失败阶段和本机声明的动作。仅在没有访问墙且有具体诊断依据时，允许一次有区别的补救（如已声明且验证可用的网页后端或普通公开 HTTP）；同 URL 不无限重试，不自动升级或重新安装。
- NEED_SETUP：说明缺少什么，不自动安装渠道或索取密钥。安装/配置须有独立授权；有其他已经获准且适合的公开读取能力时可使用。
- NEED_LOGIN、PLATFORM_BLOCKED、RATE_LIMITED、BUSY：停止本次受限尝试，记录原因和可得等待时间；不换账号、后端或浏览器规避。既有公开结果可以保留，但不能用其证明已读到受限部分。
- 所有获准读取仍失败时，才保存 failed 元数据并明确报告未完成；用户要求在线时不改为手工导入。

## 视频与交付

`read` 的视频结果可能只有简介；字幕必须调用本机声明的 subtitle 动作并实际得到文本，保留语言、类型、时间戳和多 P 范围。没有字幕时，仅在已有工具与服务额度获得授权后才转录；不自动使用 Groq/OpenAI 等收费或耗额服务。

B站扫码程序退出码0不单独证明登录有效。用户已确认扫码，但 Agent Reach 仍返回 NEED_LOGIN 时，先核对官方工具的登录状态与隔离会话是否一致；未确认可用会话前，不反复要求扫码、删除已有状态、导入个人浏览器凭据或换后端重试。把登录状态异常与“视频没有字幕”分开记录；只有实际返回字幕正文后才宣称字幕读取成功。

本机已验证的空会话兼容登录与结构化字幕验收见 [bilibili-login.md](bilibili-login.md)。仅在版本与故障条件匹配、用户已同意本人登录时使用；已有可用会话不再扫码。统一字幕结果若无时间戳，从同一原生工具取得首P from/to/content，不把简介当字幕，也不把首P称为全集。

取得资料后继续执行 Guidekeep 的结构化、置信度、归档与验证四段流程。快照按 UTF-8 原始字节保存，核对其与 original.text 的 SHA-256；原图内嵌 HTML，再用系统命令测量文件字节数并实际打开验证搜索、分支与离线显示。不要到“Agent Reach 返回成功”就停止交付。
